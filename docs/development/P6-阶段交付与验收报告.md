## 3. 管理面板效果说明

### 3.1 整体结构

```text
权限管理
├── Segmented Control：角色模板 / 成员授权 / 变更记录
├── Tab 1 角色模板
│   ├── L1 / L2 / L3 等级切换
│   └── 按模块折叠的权限列表（开关 + Scope 下拉）
├── Tab 2 成员授权
│   ├── 左侧成员列表（搜索、头像、等级徽章、部门）
│   └── 右侧权限矩阵（继承 / 允许 / 拒绝 + Scope）
└── Tab 3 变更记录
    └── 最近 50 条权限变更时间线
```

### 3.2 Apple 风视觉

- 顶部与等级切换使用 **Segmented Control**：浅灰轨道 + 白色选中块 + 细阴影。
- 内容区使用 **Inset Grouped**：大圆角、半透明毛玻璃、1px 发丝线分隔。
- 权限开关为 **iOS Switch**：蓝色轨道、白色圆形滑块、180ms 过渡。
- 风险级使用低饱和系统色徽章：低（绿）/ 中（蓝）/ 高（橙）/ 关键（红）。
- Scope 下拉保持系统设置风格，聚焦时白底 + 蓝色光圈。
- 存在未保存改动时，底部出现 **粘性保存条**（毛玻璃 + 大阴影），提供「放弃 / 保存更改」。
- 移动端 ≤900px：成员列表与权限面板改为上下布局，行内控件换行。

### 3.3 交互细节

- **角色模板**：只显示当前等级上限内的节点；L1 模板只读并提示“默认全量”。
- **成员授权**：每行三态：
  - `继承`：不写个人授权行，跟随角色模板；
  - `允许`：写 allow 行，并可选择 Scope；
  - `拒绝`：写 deny 行，`deny` 优先于模板与 allow。
- **模板默认提示**：继承下拉中直接显示“继承（本部门 / 未开启）”。
- **覆盖计数**：成员头部显示“模板 N 项 · 个人覆盖 M 项”。
- **恢复默认**：二次确认后清空个人覆盖，回到角色模板。
- **脏检查**：切换 Tab、切换等级、切换成员、关闭页面都会提示未保存。
- **搜索**：模板与成员面板都支持按名称、描述、Key 搜索；模块可折叠。

## 4. 逻辑说明

### 4.1 读取链路

1. 页面在 `withUserContext` 事务内解析 `ResolvedPermissions`。
2. 使用保护区能力 `protected:permission_grant` 判定是否 L1。
3. 读取 `role_templates` / `role_template_grants` / `memberships` / `user_permission_grants` / `audit_events`。
4. 目录元数据来自 `catalog.ts`，只下发渲染所需字段（名称、描述、风险、允许 Scope、是否可授予）。

### 4.2 写入链路

```text
Client 草稿
  → Server Action（requireSession + withUserContext）
  → requireProtectedCapability(protected:permission_grant)
  → canGrant 逐条校验：等级上限 / 可授予 / Scope 合法 / 写动作禁 DEPT_TREE
  → app.save_user_permission_grants / save_role_template_grants
      ├── L1 校验
      ├── 整体替换（先删后插）
      ├── DEPT/DEPT_TREE 自动写入 scope_id
      └── permission_revisions.version + 1
  → auditInTx（与授权写入同事务）
  → revalidatePath
```

### 4.3 生效与缓存

- 权限快照不落缓存，页面均为动态渲染。
- 保存后 `revalidatePath('/settings/permissions')`、`/me/permissions`、`/`（layout）。
- 目标成员下一次请求读取到新的 `permission_revisions.version` 与授权行，立即生效。
- 多任用用户仍按当前部门上下文解析，不合并授权。

### 4.4 安全边界

- 授权表仍对 `jxf_app` 撤销 `INSERT / UPDATE / DELETE`，只能通过 SECURITY DEFINER 函数写入。
- `L1` 模板不可修改；`L1` 成员不可配置个人授权（默认全量）。
- 系统保留节点（`member:level`、`token:issue`、`platform:*`）不可通过面板授予。
- 模板只暴露 allow；deny 仅用于成员个人覆盖，避免不可见的多层拒绝。
- 审计记录与授权写入同事务，任一步失败整体回滚。

## 6. 人工验收步骤

1. 用 L1 登录，侧栏应出现「权限管理」。
2. 打开 `/settings/permissions`，默认停在「角色模板 · L2」。
3. 关闭一个 L2 权限开关 → 底部出现保存条 → 保存 → 提示成功。
4. 切到「成员授权」，选择一名 L3 成员。
5. 将一个节点从「继承」改为「允许」，选择 Scope → 保存。
6. 刷新页面，覆盖应保留，头部「个人覆盖」计数增加。
7. 点击「恢复默认」并确认，覆盖清空。
8. 切到「变更记录」，应看到刚才的模板/成员变更。
9. 用该成员登录（或查看 `/me/permissions`），确认有效权限已变化。
10. 将浏览器缩放到移动端宽度，确认成员列表与权限行改为上下布局。
