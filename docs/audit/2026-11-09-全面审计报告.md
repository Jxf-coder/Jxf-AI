### P1-HIGH

#### SEC-01 6 张 Auth.js 表未启用 RLS，业务角色却拥有默认全 DML

- 现象：`users`、`accounts`、`sessions`、`verification_tokens`、`user_email_identities`、`app_versions` 六张表既没有 `enable row level security`，也没有被 `REVOKE`；而初始化脚本为迁移角色设置了默认权限，业务角色自动继承全部 DML。
- 证据：
  - `docker/postgres/00-init.sh:91-96` — `ALTER DEFAULT PRIVILEGES ... GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO <app_user>`。
  - `db/policies/` 全部 32 个策略文件：RLS 覆盖 53 张表，与本仓库 59 张表比对后缺口正是上述 6 张（脚本比对结果）。
  - `src/lib/db/pool.ts:18-25` 应用连接串使用 `APP_DATABASE_URL`（业务角色）；`src/auth.ts:18-26` 的 DrizzleAdapter 复用同一个连接池，因此这 6 张表对业务角色长期可读写。
- AOCI Entry：`users[EI9T]`、`accounts[RI7T]`、`sessions[SI6T]`、`verification_tokens[SI5T]`、`user_email_identities[EI6T]`、`app_versions[HO7T]`；代码侧 `auth.ts`、`pool.ts`。
- 真实库复核（2026-11-09，只读目录查询，以 `jxf_app` 连接，不读业务数据）：

  ```text
  GRANT users/accounts/sessions/verification_tokens/user_email_identities/app_versions
        = DELETE,INSERT,SELECT,UPDATE
  RLS   users/accounts/sessions/verification_tokens/user_email_identities/app_versions = false
  RLS   department_closure = true
  ```

  结论：该风险已由「静态假设」升级为「现场确认」，不是误报。
- 影响：`users.password_hash`、`sessions`、`verification_tokens` 处于「无行级隔离」状态。当前缓解因素有两点（都只是概率性缓解，不是控制项）：全仓未发现动态 SQL（唯一字符串拼接见下文 POS-07 属白名单列名）；私有化交付为单租户。一旦出现注入、越权查询或后续误用 `getPool().query` 直查 `users`，即可横向读取口令哈希。
- 建议（按优先级）：
  1. 为 `user_email_identities`、`app_versions` 补 RLS 策略（前者按 `tenant_id + user_id = app.current_user_id()`，后者只读放行）；`app_versions` 的健康检查已走 `app.current_app_version()`，可直接 `REVOKE` 表的直连权限。
  2. `users` 收回业务角色的 `SELECT/UPDATE`，认证链路改为专用 `jxf_auth` 角色或 `SECURITY DEFINER` 函数（现有 `app.user_department_ids()` 已是此模式）。
  3. `accounts/sessions/verification_tokens` 仅由 Auth.js 使用，建议整体从业务角色收权。
  4. 收权后用 `npm run audit:grants` 与集成测试 `test:rls` 回归。
- 处置（2026-11-09 第二批）：`db/policies/035_users_rls.sql` 为 `users` 启用行级安全。读 = 本人 / L1 / 可读部门内仍在岗的成员；写 = 本人改资料、L1 改全部、L2 只改可读部门的成员；不建 DELETE 策略并收回 `delete` 授权；Auth.js 的 `jxf_auth` 走独立放行策略。无上下文与跨部门的三个查询点改走 `SECURITY DEFINER`：`app.user_status`（会话校验）、`app.user_id_by_email` / `app.user_id_by_phone`（唯一性探测）、`app.ensure_user`（按手机号复用既有人员）。实测：匿名 0 行、L1 5/5、L3 3/5 且改他人 0 行。`test:rls` 新增 6 条断言（现 39 项）。

#### REL-01 应用池 `query_timeout=3s` 对知识库重查询偏紧，worker 池反而无超时

- 证据：`src/lib/db/pool.ts:24`（`query_timeout: 3_000`）；`src/worker/main.ts:605-609`（worker 池只设 `max: 4`）。
- 影响：慢盘或大文档向量写入可能触发误超时；worker 侧长事务则可能无限挂住连接。

#### REL-02 已捕获异常直接置 `failed`，`attempts` 重试只对进程崩溃生效

- 证据：`src/worker/main.ts:577-590`（catch 分支直接 `finish(... "failed")`）；`src/lib/runtime/claim.ts:23-24,110-134`（上限 3 次，仅对 `queued/interrupted/running+租约过期` 生效）。
- 影响：与「failed = 需人介入、interrupted = 可续跑」的设计一致，属有意取舍；但瞬时故障若在 catch 层被吞掉，不会走重试。
- 建议：在文档中明确该语义（当前 AOCI Entry 已写「3 次进 failed」，易被误读为「任意失败重试 3 次」）。
- 处置（2026-11-09）：语义已写入架构与运维文档。`Milestone3-运行态数据模型.md` §4.4 说明执行器 catch 异常直接 `failed`、不消耗 `attempts`；§4.5 补齐 `attempts < 3` 的领取条件、60 秒巡检语句与「只在领取时递增」的准确含义表（崩溃/超时 → `interrupted` 需人工「继续」；catch 异常 → 一次即 `failed`；累计派发 3 次 → 巡检置 `failed`）。`ops-runner.md` 新增「与运行时队列（runs）的收口语义差异」一节，区分 `ops_tasks`（runner 收口为 `failed`）与 `runs`（worker 收口为 `interrupted`）。

## 五、值得保留的工程实践（正向确认）

- **类型与守卫**：`tsc --noEmit` 退出码 0；`verify:guards` 覆盖 129 个入口、`uncovered=0`，13 条白名单每条都写明了豁免理由，不是永久豁免区。
- **权限模型**：`catalog.ts` 为唯一真相源，42 个键 = 12 个分组 + 25 个权限节点 + 5 个保护区能力（`protected:secrets/root_account/permission_grant/tenant/protected_path`），保护区永远只绑 L1 的设计在代码层有对应守卫。
- **租户隔离**：`withUserContext` 201 处 / 58 文件，每次请求一个事务 + `set_config(..., true)`（等价 `SET LOCAL`），无身份时 `access_level` 为空 → 策略全不命中，是真正的 fail-closed。
- **前端边界**：231 个 TS/TSX 文件中，`"use client"` 组件零引用 `@/lib/db`、`@/lib/permissions/server`、`next/headers`、`@/lib/env`。
- **队列语义**：`SKIP LOCKED` + 90s 租约 + 30s 心跳 + 60s 巡检 + 3 次上限，`interrupted` 与 `failed` 严格分离，启动时把他人 `running` 收口为 `interrupted`。
- **备份恢复**：`restore --verify` 会校验 manifest 的 SHA-256、把 dump 恢复进影子库并比对关键表行数，再清理影子库——这是可演练的恢复，不是纸面预案。
- **健康探针**：`/api/health/live` 不依赖数据库，`/api/health` 校验 pgvector/pg_bigm/pg_trgm 扩展与 `app_versions` 版本，两者职责分离。
- **MCP 治理**：令牌只存 SHA-256、绑定任用（离岗即失效）、scope 限工具/产线、写操作走审批、每次调用写审计。
- **无动态 SQL**：全仓唯一 SQL 字符串拼接在 `src/lib/knowledge/cards.ts:1069-1093`，列名来自固定分支白名单，值全部参数化。
- **代码卫生**：`src/` 内零 `TODO/FIXME`。
